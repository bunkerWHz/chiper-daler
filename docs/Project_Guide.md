# Где что менять

Начните с готовой сцены персонажа или ресурса предмета. Большинство настроек
доступны в Inspector; открывать скрипты для изменения чисел и рисунка не нужно.

## Разобраться в компонентах

[Справочник компонентов](Components.md): назначение каждого компонента,
когда его применять, зависимости, настройки, ограничения и примеры сборок.
Начните с таблицы «Быстрый выбор», если пока не знаете название компонента.

[Характеристики Actor](Actor_Stats.md) — пополняемый список статов, атаки,
скорости атаки, ресурсов и параметров DOT. В нём отдельно отмечены работающие
механики, неактивные поля и правила, которые ещё предстоит определить.

## Уровни

Рабочая папка — `levels/`, пустой шаблон — `levels/LevelTemplate.tscn`.
[Создание уровней](Level_Authoring.md): структура сцены, слои, лестницы,
правила размещения объектов и проверка готовой локации.

## Проверить результат

Откройте `tests/MovementSandbox.tscn` и запустите текущую сцену. Для автоматической
проверки из корня проекта:

```sh
godot --headless --path . --script tests/run_tests.gd
```

Зависимости, запуск отдельных групп и особенности Windows описаны
в [Testing.md](Testing.md). После добавления новых скриптов сначала откройте
проект в редакторе, чтобы Godot обновил список классов.

## Персонаж

Откройте `game/player/Player.tscn`. Настройки находятся под `_Components`.

| Что изменить | Где в Inspector |
| --- | --- |
| Скорость, прыжки, разгон | MovementComponent → Config: Ground movement, Jumping, Acceleration |
| Обычный и тяжёлый удар | AttackComponent → Config: Light attack, Heavy attack, Recovery and critical hit |
| Базовый урон, отбрасывание, зона удара | HitboxComponent и его Area2D/CollisionShape2D |
| Наложение горения, яда и других DOT при попадании | HitboxComponent → Status Effects |
| Сопротивления каждому типу DOT | StatusEffectComponent → Dot Resistances → Resistance |
| Сила, ловкость и другие базовые характеристики | CharacterAttributesComponent → Base attributes |
| Здоровье и нагрузка от характеристик | CharacterAttributesComponent → Derived values |
| Базовое здоровье | HealthComponent → Config |
| Начальные предметы | InventoryComponent → Config |
| Начальные наборы оружия | EquipmentComponent → Starting Main Hand Ids / Starting Off Hand Ids |
| Время смены наборов оружия | EquipmentSwapComponent → Base Duration; CharacterAttributesComponent → Action Speed → Attack Speed Multiplier |
| Полоска переодевания над головой | EquipmentSwapView в сцене игрока; Position задаёт положение |
| Заготовка анимации переодевания | `_Visual/AnimationPlayer` → equipment_swap |
| Рисунок персонажа и эффекты предметов | AnimationComponent → Character art / Item effects |
| Клипы анимации | `_Visual/AnimationPlayer` |

Встроенные конфигурации общей сцены компонента могут использоваться несколькими
персонажами. Для изменения только текущего персонажа сначала выберите
**Make Unique** у ресурса. Кнопка копирования врага делает конфигурации
независимыми автоматически.

## Враг

[Коллекция монстров и сцена проверки](Monster_Collection.md).

Наземный шаблон — `game/enemy/GroundDummy.tscn`, летающий — `FlyDummy.tscn`.
У обоих масштаб `1, 1` и не назначена графика. Готовые монстры коллекции
перечислены в Monster_Collection.md и находятся в отдельных папках `game/enemy/monsters`.
[Создание независимой копии](Enemy_Copy.md) занимает выбор имени и нажатие
кнопки. Затем меняйте рисунок, коллизии и конфигурации в новой сцене.

У летающего врага патруль настраивается в EnemyFlightComponent,
а преследование — в EnemyChaseComponent. Подготовка
удара настраивается через EnemyAttackComponent → Config → Windup, дистанция —
через Engagement. Длительность самой атаки задаёт клип, как описано
в [Enemy_Timing.md](Enemy_Timing.md). Предупреждения EnemyAuthoringChecks
помогают найти пропущенные ресурсы и события до запуска.

## DOT и сопротивления

[Инструкция по DOT](DOT.md): создание новых типов, наложение через атаку или
напрямую, время первого тика, повторное наложение и расчёт сопротивлений.

Новые эффекты создаются в `features/status/DotEffectGenerator.tscn` кнопкой
**Create DOT resource**. Генератор обновляет общий каталог: новый тип автоматически
появляется в списках сопротивлений с 0%, сохраняя прежние настройки.
Для ресурсов, созданных вручную, используйте **Refresh DOT catalog**.

Первый урон DOT происходит через заданный интервал, а не при наложении.
Сопротивление 30% превращает тик на 10 урона в 7; 100% убирает урон тиков,
но не препятствует наложению эффекта и не уменьшает исходный удар.

## Предмет

Подробная [настройка дропа с монстров](Loot_Setup.md): предметы, количество,
вероятности, независимые таблицы дропа и проверка подбора.

Откройте нужную категорию в `game/items`. Для нового предмета скопируйте
ресурс из `game/items/templates`: [инструкция](../game/items/README.md).
В ItemData находятся название,
описание, иконка, масса и размер стопки. В разделе Profiles:

| Профиль | Настройка |
| --- | --- |
| Equipment Profile | Слоты, урон, защита; требования к статам удалены, требования пассивных навыков запланированы — см. [решение](Actor_Stats.md#пассивные-навыки-и-требования-предметов) |
| Weapon Profile | Режим, разрешённые действия, занятость рук, дальность и критический урон |
| Offhand Profile | Блок и парирование |
| Consumable Profile | Эффект использования; для фляги — также максимальные заряды |
| Ammunition Profile | Тип боеприпаса |

Отсутствующий профиль означает отсутствие соответствующего свойства.
Список работающих параметров и границы механики — в [Item_Parameters.md](Item_Parameters.md).
Поля Planned (inactive) сохраняют заготовки данных и не влияют на игру.

## Интерфейс и код

В `features/inventory/ui` находятся ItemCell.tscn, ItemDetailsView.tscn и общая
InventoryTheme.tres. Меняйте оформление в теме, ячейку и карточку — в их сценах.
Общий экран находится в InventoryMenuComponent.tscn. Разметку можно менять
без обновления тестовых чисел отступов, сохраняя обязательные элементы.

Правила надевания и перемещения принадлежат EquipmentComponent; меню только
вызывает операции и показывает причины отказа. EquipmentInputComponent
переводит команды игрока в переключение наборов. Владение паузой экрана
реализовано через PauseLease.

Общие заготовки предметов для тестов находятся в `tests/fixtures/ItemFixtures.gd`.
Добавляйте туда повторяющееся создание данных, а проверки поведения оставляйте
рядом с соответствующей механикой. Новые Node вне дерева регистрируйте через
`track()`, чтобы тесты освобождали их после завершения.
