# Какие параметры предметов работают

Целевая структура и стартовые значения приняты 2026-09-17: [Создание оружия и брони](Item_Creation_Design.md). Ниже описана текущая реализация; будущие формулы атаки учитывают характеристики персонажа и баффы, не изменяя базовые данные предмета.

Сверено с игровым кодом 2026-09-13 при составлении справочника компонентов.
Наличие поля в ресурсе или его
отображение в меню само по себе не означает влияние на механику.

## Новое правило требований предметов

Принято: предметы требуют уровни пассивных навыков, а не значения базовых статов.
Например, меч — «Владение мечами 3», тяжёлая броня — «Ношение тяжёлой брони 5».
Правило и план миграции описаны в [Характеристиках Actor](Actor_Stats.md#пассивные-навыки-и-требования-предметов).
Проверки навыков ещё не реализованы; требования STR/DEX/INT/END/WIS удалены. Будущие формулы итогового урона описаны в новом решении.

## Отображение экипировки основного героя

Основной герой — Darklight. Его риг сохраняет анимации и крепления при смене предмета.

| Поле | Текущее поведение |
| --- | --- |
| ItemData.icon | Только изображение в интерфейсе |
| ItemData.equipped_texture | Картинка Sprite2D в руке, имеет приоритет над equipped_visual |
| ItemData.equipped_visual | Необязательная сцена предмета; начало координат — место хвата |
| ItemEquipmentProfile.allowed_slots | Допустимые слоты экипировки в инвентаре |
| ItemEquipmentProfile.display_slot | Рука отображения: Same As Equipment по умолчанию, Main Hand или Off Hand |

Лук и арбалет занимают MAIN_HAND, а отображаются в OffHand. Колчан виден при
экипированных стрелах или болтах активного набора; при снятии или расходе последнего
боеприпаса скрывается. Без equipped_texture и equipped_visual предмет в руке не виден.
Подробности: [создание ресурсов предметов](../game/items/README.md) и
[работа с ригом](../game/player/darklight/README.md).

## Текущие параметры

Метательные предметы используют `ItemData.projectile_profile` (ItemProjectileProfile):
texture, speed, gravity, lifetime, damage и knockback работают при выпуске.
Предмет назначается в быстрый слот и расходуется по одной единице при отпускании R.
См. [Aiming.md](Aiming.md).

| Поле ItemWeaponProfile | Статус | Где используется |
| --- | --- | --- |
| combat_mode | Работает | EquipmentComponent выбирает доступный режим действий |
| visual_archetype | Устаревшее поле | Сохранено для совместимости ресурсов; потребитель старого визуала удалён, на Darklight не влияет |
| family | Описание | Название семейства в карточке, отдельных правил семейства нет |
| handedness | Работает | Занятость рук и совместимость экипировки |
| available_actions | Частично работает | Attack, Guard, RangedWeapon и Magic проверяют доступные действия; RELOAD пока не используется |
| critical_damage_multiplier | Работает для ближнего боя | AttackComponent передаёт множитель в HitboxComponent |
| ammunition_type | Работает | EquipmentComponent подбирает совместимые боеприпасы; RangedWeaponComponent расходует надетую в OFF_HAND стопку инвентаря |
| ammunition_profile.projectile_scene | Работает | Сцена снаряда этой стопки: арт, коллизия, `sticks` и `pierce`. Пусто — способность собирает генерический снаряд кодом |
| primary_damage_type | Запланировано | Разных расчётов для slash/pierce/strike/magic пока нет |
| moveset_id | Запланировано | Выбор набора движений по идентификатору не реализован |
| attack_speed_multiplier | Запланировано | Длительности берутся из конфигурации атаки |
| reach_multiplier | Работает для ближнего боя | AttackComponent задаёт горизонтальный масштаб и смещение HitboxComponent на время удара |
| stagger_power | Запланировано | Сила оглушения оружия не подключена |
| strength_scaling | Отменено | Не используется; не подключать зависимость оружия от силы |
| dexterity_scaling | Отменено | Не используется; не подключать зависимость оружия от ловкости |
| intelligence_scaling | Отменено | Не используется; не подключать зависимость оружия от интеллекта |

Урон и защита экипировки сейчас читаются из ItemStats. Требования к базовым
характеристикам проверяет CharacterAttributesComponent. Дополнительный базовый
урон хитбокса настраивается отдельно от предмета.

Дальность ближнего оружия умножает горизонтальное смещение и ширину хитбокса,
сохраняя высоту. Значение фиксируется в начале обычной или тяжёлой атаки;
следующая атака использует новое оружие. Завершение и прерывание возвращают
исходную геометрию. Значение 1 сохраняет размеры сцены, 0.7 сокращает дальность,
1.6 увеличивает её. Диапазон ограничен 0.1–5; дальность снарядов не меняется.
Это изменение игрового баланса: ранее записанные множители теперь действуют.

У ItemOffhandProfile работают block_damage_reduction и parry_window_multiplier.
guard_stability пока не используется; из флагов действий offhand игровые
проверки потребляют GUARD и PARRY. CAST/AIM/FIRE пока не подключены.
Poise брони суммируется в EquipmentComponent, но на оглушение пока не влияет.

Карточка и сводка инвентаря не показывают эти неработающие боевые параметры.
Данные ресурсов сохранены. В Inspector неактивные числовые поля сгруппированы
под «Planned (inactive)». При подключении механики нужно перенести её поле
в рабочую группу, добавить проверку влияния на игровой результат и вернуть
соответствующее значение в карточку.

## Вес и цена продажи

`ItemData.weight` и `ItemData.sell_price` — общие данные предмета, а не поля
боевого профиля. Оба видны в карточке предмета.

| Поле | Статус | Где используется |
| --- | --- | --- |
| weight | Работает | Общий вес в строке инвентаря (сумка и надетое вместе), нагрузка экипировки, экран создания персонажа, карточка предмета |
| sell_price | Заготовка | Показывается в карточке предмета (`ItemData.is_sellable()`); механики продажи ещё нет. Ноль означает «не продаётся»: у таких предметов строка цены в карточке не выводится |

При создании предмета оба поля равны 1. Продавать нельзя фласки и боеприпасы:
фласки выпивают, стрелы и болты расходуются выстрелом, поэтому у них
`sell_price = 0` (фласки вдобавок весят 0, то есть `weight = 0`). Правило
проверяют `tests/item_audit.gd` и `tests/test_item_authoring.gd`: у флакона и
любого предмета с `ammunition_profile` цена обязана быть 0, у остальных — больше
нуля. Стартовые значения и правила — в
[решении по предметам](Item_Creation_Design.md).

## Решение в рамках рефакторинга

Из заготовленных числовых полей подключена дальность ближнего удара: она имеет
прямой смысл относительно существующего хитбокса и проверяется без введения
новой подсистемы. Остальные поля сохранены как явно неактивные заготовки.
Старые коэффициенты scaling не подключены. Новые формулы итогового урона
будут определены отдельно по решению Item_Creation_Design.md.
Скорость требует согласования всех фаз и воспроизведения анимаций;
stagger и poise — правил оглушения; moveset и тип урона — новых
боевых механик. Они не считаются работающими настройками и не показываются
в карточке. Их реализация относится к развитию боя, а не к завершению этого
рефакторинга. Это осознанная граница объёма, а не обещание скрытого эффекта поля.

## Настройки луков и арбалетов

Создавайте предмет копированием `game/items/templates/Bow.tres` или
`game/items/templates/Crossbow.tres`, затем задайте уникальный ID и название.
В инспекторе откройте **Weapon Profile → Ranged**. Это настройки конкретного
предмета; они используются при каждом выстреле.
При создании Weapon Profile с нуля выбор Combat Mode = Bow или Crossbow
автоматически создаёт Ranged, если он ещё не задан. Существующие настройки
при смене режима сохраняются; для перехода на другой тип удобнее взять его шаблон.

| Поле | Лук | Арбалет |
|---|---:|---:|
| Projectile Speed | 600 | 820 |
| Projectile Gravity | 350 | 50 |
| Projectile Damage | 18 | 24 |
| Projectile Lifetime | 2 с | 2 с |
| Shot Cooldown | 0,3 с | 0,3 с |
| Release Duration | 0,12 с | 0,12 с |
| Knockback | 160 | 160 |

Projectile Damage прибавляется к урону оружия с учётом улучшений.
Шаблоны имеют урон оружия 9 и 13, поэтому итог без улучшений — 27 и 37.
Удержание кнопки не увеличивает скорость. Начальный угол — 15°.
Старые поля RangedWeaponConfig больше не управляют выстрелами экипированного оружия.
При копировании ресурсов вручную делайте Ranged уникальным, чтобы изменения
не затрагивали другой предмет, использующий тот же ресурс.
