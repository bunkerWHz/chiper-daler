# Периодический урон (DOT)

Горение, кровотечение, яд и любые новые названия используют один `StatusEffect`.
Готовые примеры находятся в `game/status`; их параметры одинаковые и служат
отправной точкой для настройки, а не готовым балансом.

## Создать свой эффект

1. Откройте `features/status/DotEffectGenerator.tscn` и выделите корневой узел.
2. Задайте `Effect Id` (например, `frost_bite`), `Display Name` (любое название),
   `Damage Per Tick`, `Tick Interval` в секундах и `Duration` в секундах.
3. Нажмите **Create DOT resource**. Результат сохраняется в
   `game/status/<Effect Id>.tres` и открывается в инспекторе. Генератор также
   добавляет его в общий `game/status/DotCatalog.tres`: у всех профилей
   сопротивлений появляется новый тип со значением 0%, без изменения старых настроек.

Существующие файлы не перезаписываются. Для изменения готового эффекта откройте
его `.tres`. Генератор автоматически выбирает Debuff. Отображаемое имя свободное;
Effect Id — технический уникальный идентификатор без пробелов.

## Сопротивления DOT

На игроке или монстре выберите `_Components/StatusEffectComponent` и раскройте
ресурс **Dot Resistances → Resistance**. Список полей строится из общего каталога
по `Effect Id`: Burning, Bleeding, Poison и все новые типы. Введите процент от 0
до 100 для нужного типа. Значения принадлежат конкретному персонажу; экземпляры
сцен не изменяют сопротивления друг друга.

Формула: **урон тика × (1 − сопротивление / 100)**. Например, 30% сопротивления
горению превращает тик на 10 урона в 7. При 100% эффект по-прежнему накладывается
и истекает в обычное время, но не наносит урон. Длительность, частота тиков,
шанс наложения и обычные удары сопротивлением DOT не меняются. Значение читается
при каждом тике: изменение сопротивления влияет и на уже действующий эффект.
По умолчанию все сопротивления равны 0%, поэтому прежний баланс сохраняется.

Новые типы через генератор появляются в списке автоматически, в том числе
у уже созданных профилей. В профиле сохраняются только значения по ID; копировать
все профили при расширении каталога не нужно. Каталог хранит ссылки на ресурсы
DOT, поэтому список доступен и в экспортированной игре, без сканирования файлов.

Если создаёте `.tres` вручную, нажмите **Refresh DOT catalog** на генераторе:
он перечитает файлы `.tres`/`.res` непосредственно в `game/status`. Обычные статусы
без периодического урона пропускаются, дубли ID отклоняются. После удаления
ресурса также обновите каталог. `Effect Id` сохраняйте стабильным: изменение ID
создаёт другой тип с исходным сопротивлением 0%; изменение Display Name безопасно.
Старые значения удалённых типов сохраняются скрыто и восстановятся при возврате ID.

Для кода: `dot_resistances.get_all()` возвращает полный актуальный словарь
`ID → процент`; `set_percent(id, value)` меняет значение, `get_percent(id)` читает
его. Отсутствующий профиль или неизвестный ID без заданного значения означают 0%.
Этот этап задаёт собственные сопротивления персонажа; бонусы сопротивлений
от экипировки пока не подключены.

## Наложение

Чтобы атака накладывала DOT:

1. Создайте эффект через генератор или выберите готовый ресурс в `game/status`.
2. Откройте сцену атакующего и выберите `_Components/HitboxComponent`.
3. Добавьте ресурс в массив **Status Effects**. Можно назначить несколько разных DOT.
4. На цели настройте **StatusEffectComponent → Dot Resistances → Resistance**.
5. Сохраните сцены и проверьте попадание в игре.

Эффекты накладываются после попадания, реально снявшего здоровье. Блокирование
всего урона и неуязвимость предотвращают наложение. Смертельный удар не оставляет
эффектов на мёртвой цели. По умолчанию массив пуст: атаки не получают DOT автоматически.
Отдельного броска вероятности нет: допустимые назначенные эффекты накладываются
при каждом таком попадании. Сопротивление DOT уменьшает последующие тики,
а не вероятность наложения и не исходный урон удара.

Для заклинания, снаряда или другого источника, использующего `HitData`, заполните
его `status_effects` перед `receive_hit()`. Для ловушек и других прямых источников
вызовите `target.get_component(StatusEffectComponent).apply_effect(effect)`.
Это общий API; отдельные настройки DOT в интерфейсах оружия и магии не добавлены.
Прямой `apply_effect()` не проходит через Hurtbox: блок и неуязвимость от удара
не проверяются. Источник сам решает, когда вызывать наложение. Сопротивление
учитывается при тиках независимо от способа наложения.

У получателя нужны `HealthComponent` и `StatusEffectComponent` под `_Components`.
Игрок, оба шаблона врагов и все готовые монстры уже содержат эти компоненты.
Любому другому разрушаемому Actor их можно добавить так же.

## Когда наносится урон

**При наложении DOT мгновенного тика нет. Сначала проходит Tick Interval,
затем наносится первый периодический урон.** Урон исходного удара — отдельное
событие: он снимает здоровье сразу при попадании.

Пример: попадание наносит 20 урона и накладывает горение с `Damage Per Tick = 10`,
`Tick Interval = 1`, `Duration = 3`. У цели 30% сопротивления горению:

| Время после попадания | Событие | Урон |
| --- | --- | --- |
| 0 секунд | Исходный удар и наложение горения; тика ещё нет | 20 от удара |
| 1 секунда | Первый тик | 10 × 0,7 = 7 |
| 2 секунды | Второй тик | 7 |
| 3 секунды | Третий тик, затем окончание эффекта | 7 |

Итого: 21 урона от DOT и 20 от удара, если цель выжила, эффект не сняли
и сопротивление не менялось. При 100% сопротивления горению урон удара остаётся
20, каждый тик даёт 0. Здесь 20 — уже фактический урон удара после его обычной защиты.

Без повторного наложения число тиков равно `floor(Duration / Tick Interval)`.
При длительности 2,5 секунды и интервале 1 секунда будут два тика — на 1-й и
2-й секундах; на 2,5-й эффект закончится без дополнительного урона.
Если длительность меньше интервала, эффект истечёт без единого тика.

Повторное наложение того же ID обновляет длительность, но при прежнем интервале
не откладывает ближайший тик. Например, повтор на 0,75 секунды при интервале
1 секунда оставит первый тик на 1-й секунде от исходного наложения, то есть
через 0,25 секунды после повтора. Урон не складывается в стаки; применяются
параметры последнего наложения. При изменении интервала его отсчёт начинается заново.

## Правила

- Первый тик происходит через `Tick Interval`, не сразу при наложении.
- Базовый урон равен `Damage Per Tick`; урон тика после сопротивления =
  `Damage Per Tick × (1 − Resistance / 100)`, номинальный DPS = этот урон / интервал.
- Тик на точной границе окончания учитывается, неполный интервал урона не даёт.
  Например, 5 урона раз в секунду на 5 секунд дают 25 урона.
- Разные ID действуют одновременно. Повторный ID обновляет длительность и
  параметры без суммирования стаков. При неизменном интервале следующий тик
  не откладывается; при смене интервала отсчёт тика начинается заново.
- Ресурс копируется при наложении: таймеры целей независимы, редактирование
  исходного ресурса не меняет уже действующий эффект.
- Тики учитывают сопротивление своему DOT, затем напрямую снимают здоровье:
  без обычной брони, блока, критов, отбрасывания, оглушения и проверки
  неуязвимости от удара/уклонения. Смерть запускается через `HealthComponent`.
- Смерть и отключение компонента снимают эффекты. `clear_debuffs()` снимает DOT;
  отдых игрока уже использует этот метод. Пауза останавливает обычную обработку.
- При просадке кадров учитываются все полные тики в пределах длительности.
- `Damage Per Tick = 0` оставляет обычный временный статус без урона.

Для реакции интерфейса доступны `effect_applied`, `effect_removed` и
`effect_ticked(effect, applied_damage)`. Отдельная панель и визуальные эффекты
для названий DOT не создаются генератором.

Проверки: `--headless --path . --script tests/run_tests.gd -- dot_resistances dot_effects status_effect combat`.
