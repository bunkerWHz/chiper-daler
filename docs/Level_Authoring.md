# Создание уровней

Этот документ — пополняемый стандарт новых игровых уровней. Тестовые сцены
проверяют механики, но не определяют архитектуру и оформление игровых локаций.
При изменении соглашений обновляем этот документ и, если нужно, шаблон.

## Статус и рабочая папка

- Шаблон: `levels/LevelTemplate.tscn`.
- Каждый уровень: `levels/<level_name>/<LevelName>.tscn`.
- Названия папок — `snake_case`, сцен и нод — `PascalCase`.
- Уникальные под-сцены и ресурсы уровня храним рядом с ним. Общие игровые
  объекты храним в тематических папках `game/`, механики — в `features/`.
- Общий TileSet биома можно использовать в нескольких уровнях. Изменение
  такого ресурса влияет на всех пользователей; для локального варианта
  создаём отдельный ресурс, а не незаметно меняем общий.

Шаблон сейчас содержит только пустые ноды, маркер входа и настройки отображения.
В нём нет игрока, TileSet, изображений, звуков, скриптов или подключённого HUD.
Запуск показывает пустой экран. Имена контейнеров не запускают игровые механики.

## Создать уровень

1. Создать папку уровня в `levels/`.
2. Через Duplicate скопировать шаблон, переместить копию и переименовать сцену
   и её корень. Пока используем независимую копию, без наследования от шаблона.
3. Собрать простую геометрию, определить вход, выход и безопасную точку появления.
4. Подключить игрока, камеру, переходы и интерфейс. Проверить движение и прыжки.
5. Добавить противников, объекты и контрольные точки, затем оформление и звук.

Изменения шаблона не переносятся в существующие копии автоматически.
При обновлении стандарта отдельно проверяем уже созданные уровни.

## Структура

| Путь | Назначение |
| --- | --- |
| `Background/Sky` | Изображение неба; Sprite2D без текстуры в шаблоне |
| `Background/FarBackground` | Дальний план Parallax2D, начальная скорость 0.2 |
| `Background/NearBackground` | Ближний план Parallax2D, начальная скорость 0.5 |
| `Terrain/BackDecor` | Тайловый декор позади игрового действия |
| `Terrain/Solid` | Земля, сплошные платформы, стены и потолки |
| `Terrain/OneWayPlatforms` | Неподвижные платформы с проходом снизу |
| `Terrain/FrontDecor` | Тайловый декор перед игровым действием |
| `Objects/Platforms` | Движущиеся, падающие и другие платформы с поведением |
| `Objects/Climbables` | Лестницы, верёвки, лианы |
| `Objects/Interactables` | Двери, рычаги, сундуки и другие интерактивные объекты |
| `Objects/Checkpoints` | Контрольные точки и места отдыха |
| `Objects/Hazards` | Ловушки, шипы и явно размещённые зоны смерти |
| `Actors` | Место для игрока; экземпляр или создание через систему входа |
| `Actors/Enemies`, `Actors/NPCs` | Готовые сцены противников и NPC |
| `Pickups` | Подбираемые предметы |
| `SpawnPoints/DefaultSpawn` | Маркер основного входа; дополнительные входы — именованные Marker2D |
| `Transitions` | Выходы и переходы между локациями |
| `Triggers` | Области запуска событий и сценариев |
| `CameraBounds` | Место для границ и зон камеры |
| `Atmosphere/Lighting` | Освещение |
| `Atmosphere/Particles` | Частицы и погода |
| `Atmosphere/Audio` | Музыка, фоновые и пространственные звуки |
| `HUD` | CanvasLayer для общей сцены интерфейса |

Пустые контейнеры служат памяткой; заполнять все в каждом уровне не требуется.
В шаблоне нет второй камеры или фиктивного игрока. Контейнер `CameraBounds`
сам по себе не ограничивает камеру, а `DefaultSpawn` сам не перемещает игрока.

## Тайлы и порядок отрисовки

Для настройки общего ресурса используем
`levels/workshops/TileSetWorkshop.tscn` — [инструкция мастерской](../levels/workshops/README.md).
Первый подключённый набор: `assets/tilesets/green_forest/GreenForestTileSet.tres`.
Мастерская хранит образцы раскладки, внешний `.tres` — настройки самого набора.

TileSet — ресурс с изображениями и свойствами тайлов; TileMapLayer — слой карты.
Один TileSet может обслуживать несколько слоёв. Разделяем слои по назначению,
коллизии и порядку отображения, а не заводим новый слой для каждого рисунка.

- `Solid`: сплошные коллизии, настроенные в TileSet.
- `OneWayPlatforms`: односторонние коллизии, настроенные в TileSet. Имя ноды
  не включает их автоматически. Спуск вниз сквозь платформу — отдельная
  механика игрока, которой также требуется проверка.
- У обоих декоративных слоёв коллизии отключены на уровне ноды.
- Навигация тайлов отключена в шаблоне. Планирование прыжков и движения
  врагов проектируем отдельно, по требованиям конкретных механик.

Начальные значения Z: фон −100, задний декор −20, игровой план 0,
передний декор 20. HUD находится на CanvasLayer 10. Z дочерних CanvasItem
по умолчанию складывается с родительским: учитываем это у готовых сцен.
Передний декор не должен скрывать опасности и края платформ.

Размер тайла выбираем под графику биома, а геометрию — под реальные возможности
персонажа. Корень уровня, организационные контейнеры и TileMapLayer оставляем
в масштабе (1, 1); масштабом всего уровня не исправляем дальность прыжков.
Для объектов сохраняем правила AGENTS.md: исходный размер спрайта, единичный
масштаб коллизий, равномерный масштаб корня объекта. После изменения размера
проверяем совпадение изображения и физики.

## Лестницы и объекты с поведением

Стандарт для новых лестниц — отдельная повторно используемая сцена, содержащая
изображение и Area2D с формой области лазания. Графику можно собирать из
повторяющихся секций или внутреннего TileMapLayer без коллизий. Это способ
рисовать лестницу, а не замена её игровой механики.

Для обычной непрерывной лестницы предпочтительна одна область на всю длину,
а не независимый триггер на каждую ступень. Высоту задаём размером формы и
числом визуальных секций, не растягиваем всю сцену неравномерно.
Не используем сплошную коллизию земли для области лазания.
Настил у верхнего края, если он нужен, имеет свою коллизию платформы.

Перед созданием окончательной сцены лестницы определяем и проверяем вход
сверху и снизу, выход на площадку, прыжок с лестницы и потерю контакта.
Тестовая реализация может помочь проверить механику, но не считается готовым
стандартом без этой проверки. В этой задаче новая механика лестницы не создаётся.

Двери, ловушки, сундуки, движущиеся и разрушаемые платформы также оформляем
отдельными сценами. Уровень размещает объекты и связывает события; правила
их работы остаются в повторно используемых сценах и компонентах.

## Контракты будущего игрового уровня

Следующие требования нужно реализовать при подключении игрового контента;
сейчас шаблон только резервирует для них места.

- При входе выбирается именованная точка появления; персонаж оказывается
  вне коллизий, над опорой и вне опасных зон.
- Переход указывает целевую сцену и точку входа. Проверяются оба направления.
- Активна одна игровая камера. Уровень передаёт ей свои границы или зоны.
- Игрок и HUD имеют одного владельца: либо текущий уровень, либо игровая
  сессия. Не создаём дубликаты при переходах; если HUD принадлежит сессии,
  оставляем контейнер уровня пустым.
- Смерть в пропасти задаётся явно и допускает безопасные вертикальные
  переходы. Сам выход персонажа из кадра не считаем универсальным правилом смерти.
- Сохраняемым объектам нужны стабильные идентификаторы. Не привязываем
  состояние сундука или контрольной точки к порядку дочерних нод.

## Проверка готового уровня

- Все обязательные прыжки выполнимы с текущими параметрами персонажа.
- Нет застреваний на стыках, неожиданных коллизий декора и провалов под землю.
- Односторонние платформы и лестницы работают с обоих направлений подхода.
- Камера не показывает пустоту за границами; вертикальные маршруты читаемы.
- Входы, выходы, смерть и возвращение на контрольную точку проверены.
- Переходы и загрузка сохранения не дублируют игрока, HUD и одноразовые награды.
- Фон и декор не мешают видеть противников, предметы и опасности.
