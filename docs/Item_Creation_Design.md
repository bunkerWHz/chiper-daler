# Создание оружия и брони: принятое устройство

Решение от 2026-09-17. Документ фиксирует целевую структуру данных, а не
завершённую реализацию. В этой задаче меняется только документация.
Текущая реализация описана в [Item_Parameters.md](Item_Parameters.md).
При противоречии с прежними решениями о зависимости оружия от характеристик
персонажа приоритет имеет этот документ.

## Предмет и итоговые характеристики

Предмет хранит базовые характеристики. Итоговый урон вычисляется формулами
атаки с учётом параметров персонажа, баффов и контекста попадания. Формулы,
коэффициенты и порядок применения модификаторов определим отдельно.
Аналогично базовая защита брони является входом будущего расчёта защиты.
Итоговые значения не записываются обратно в ресурс предмета.

В карточке следует явно писать «Базовый урон» и «Базовая защита».
Предварительный расчёт итоговых значений для персонажа добавим вместе с формулами.
Старые поля strength/dexterity/intelligence_scaling пока не подключаем:
новое решение разрешает зависимость результата атаки от характеристик персонажа,
но не утверждает старую схему коэффициентов для каждого оружия.
Требования для экипировки по пассивным навыкам — отдельное ранее принятое решение.
«Минимальные характеристики по умолчанию» здесь означают стартовые значения
предмета, а не требования к STR/DEX или уровню персонажа.

## Общие данные

| Поле | Назначение | Стартовое значение |
|---|---|---|
| ID | Постоянный уникальный ключ | Пустой; обязательно задать перед использованием |
| Название | Отображение в игре | «Новое оружие» / «Новая броня» по шаблону |
| Описание | Необязательный текст | Пустое |
| Иконка | Изображение предмета | Общая заглушка |
| Категория и подтип | Оружие/броня и выбранный тип | Из шаблона |
| Редкость | Качество | Обычная |
| Вес | Вес одной единицы | 1 |
| Цена продажи | Базовая цена за единицу | 1 |
| Стопка | Оружие и броня не складываются | Выключена; размер 1 |
| Результаты разлома | Список «ресурс + количество» | Пустой: разлом недоступен |
| Дополнительные эффекты | Эффекты попадания или ношения | Пустой список |

Цена продажи обязательна в структуре, но благодаря дефолту не требует ручного
заполнения: `ItemData.weight` и `ItemData.sell_price` по умолчанию равны 1, и
новый предмет получает их сразу. Вес и цена 1 — стартовые значения для новых
шаблонов, а не финальный баланс: автор уточняет их под предмет. Шаблон без
собственных строк веса и цены наследует эти значения, поэтому предметов без
веса быть не должно.

Фласки — исключение: они весят 0 и не продаются, поэтому у них всегда
`weight = 0` и `sell_price = 0`. Их также нельзя выбрасывать, передавать и
выкладывать в лут.

Боеприпасы не продаются по той же причине, что и флаконы: они расходуются самим
действием, а не обмениваются. У стрел и болтов `sell_price = 0`, вес при этом
обычный. Правило «цена 0 = предмет не продаётся» читает
`ItemData.is_sellable()`, карточка предмета прячет строку цены, а каталог
проверяют аудит и тест авторинга.

Разлом может возвращать несколько ресурсов. Для каждой записи выбирается
ресурс предмета-материала и положительное целое количество (по умолчанию 1).
Рецепты, интерфейс крафта и выполнение разлома откладываются.

## Оружие

| Поле | Стартовое значение / правило |
|---|---|
| Тип | Из шаблона: меч, копьё, лук, арбалет и т. д. |
| Занятость рук | Из шаблона; обычный меч — одна рука, лук/арбалет — две |
| Базовый урон | Меч 10; лук 27; арбалет 37 |
| Тип урона | Из шаблона; меч — рубящий, лук/арбалет — колющий |
| Базовая скорость атаки | Нейтральный множитель 1; базовые фазы задаёт тип атаки |
| Дальность ближнего удара | Множитель 1 относительно базовой геометрии удара |
| Отбрасывание | Для общего ближнего шаблона 0; лук/арбалет 160 |
| Эффекты попадания | Нет |

У оружия одно понятное поле базового урона. Отдельный добавочный урон снаряда
в настройках лука/арбалета планируется убрать. Значения 27 и 37 сохраняют
нынешний результат учебного оружия без улучшений (9 + 18 и 13 + 24).
Миграция данных и поведения улучшений должна быть отдельной задачей:
сейчас улучшения повышают только часть урона оружия, а не всю сумму.
Бонусы боеприпасов, если понадобятся, определим отдельно.

### Луки и арбалеты

| Поле | Лук | Арбалет |
|---|---:|---:|
| Боеприпас | arrow | bolt |
| Скорость запуска | 600 | 820 |
| Гравитация | 350 | 50 |
| Время жизни снаряда | 2 с | 2 с |
| Базовая задержка между выстрелами | 0,3 с | 0,3 с |
| Фаза выпуска | 0,12 с | 0,12 с |

Эти параметры редактируются у конкретного предмета. Задержки — базовые данные
атаки, которые позже сможет изменять общая формула скорости; вторую независимую
настройку скорострельности вводить не нужно. Дальность полёта получается из
скорости, угла, гравитации, времени жизни и столкновений.
Начальный угол 15° остаётся общей настройкой прицеливания.
Удержание кнопки сейчас не усиливает выстрел. Перезарядка и натяжение — отдельные
будущие механики, не часть текущего решения о базовых полях.

## Броня

| Поле | Стартовое значение / правило |
|---|---|
| Слот | Из шаблона; общий Armor — грудь |
| Класс | Лёгкая; остальные классы определяются выбранным шаблоном |
| Базовая защита | 5 |
| Сопротивления | Нет бонусов; все значения 0 |
| Эффекты при ношении | Нет |

Конкретный перечень сопротивлений и правила их суммирования нужно согласовать
с системой боя. Список классов брони этим документом не расширяется:
сейчас в коде есть LIGHT, HEAVY и ROBE.

## Эффекты

Различаем эффекты при попадании и эффекты, действующие пока предмет надет.
Оружие может ссылаться на DOT (горение, яд и т. п.). У записи эффекта попадания
задаётся шанс наложения; после добавления записи стартовое значение — 100%.
Сам ресурс эффекта хранит урон тика, интервал и длительность. По умолчанию
ни одного эффекта нет. Правила DOT см. в [DOT.md](DOT.md).
Бонус брони действует при ношении и снимается при снятии предмета;
это отдельный способ применения, а не DOT по владельцу.

## Минимальный путь создания

1. Скопировать шаблон нужного типа, получив независимые вложенные профили.
2. Задать уникальный ID. Название, иконку и параметры изменить по необходимости.
3. Сохранить и добавить предмет в инвентарь, добычу или другой источник.

Шаблон должен заранее задавать согласованные слоты, режим, действия, тип урона
и боеприпасов. Автор меняет только отличия от базового предмета.
Название-заглушка допустимо для прототипа; ID остаётся обязательным.
Смена типа не должна молча стирать авторские настройки: нужен явный сброс
к дефолтам типа либо создание из другого шаблона.

## Что ещё предстоит реализовать

- Общие поля, цена продажи, шаблоны и индивидуальные параметры стрельбы уже есть.
- Результаты разлома, списки эффектов предмета и сопротивления брони по этой
  схеме ещё предстоит подключить.
- Единый базовый урон, подписи карточки, скорость ближнего оружия и согласованная
  проверка профилей требуют доработки. Тип урона пока не меняет расчёт попадания.
- Нужно убрать влияние устаревшего RangedWeaponConfig на проверку готовности
  стрельбы, оставив параметры у предмета.
- Приведение шаблонов к указанным стартовым значениям — отдельная реализация;
  текущие файлы предметов в рамках фиксации документации не меняются.
- Формулы итоговых характеристик, крафт и разлом реализуем позднее.
