# Система сохранений

## Правила игры

Один слот прохождения. «Продолжить» и «Загрузить игру» возвращают персонажа
к последнему месту **успешного отдыха**, сохраняя актуальный прогресс.
До первого отдыха точкой возвращения служит стартовая позиция персонажа.
Сохранение прогресса не меняет место возвращения.

Пример: игрок отдохнул в A, открыл сундук, улучшил оружие, перешёл в B и вышел.
При продолжении он появится в A с улучшенным оружием; сундук останется открытым.
После отдыха в B местом возвращения станет B.

При загрузке и смерти создаётся новая сцена уровня: обычные враги возрождаются,
временные эффекты и боевые действия исчезают. Здоровье и мана восстанавливаются
до максимумов с учётом сохранённых характеристик и экипировки, фляги пополняются.
Выносливость получает стартовый максимум из новой сцены. Патроны и метательные
заряды сохраняются как расходуемый запас, автоматически не пополняются.
При отдыхе обычные размещённые в сцене враги также создаются заново.

**Смерть опустошает кошелёк:** 20% янтаря теряются безвозвратно, остальные 80%
остаются на месте гибели. Возвращаемая часть округляется вниз: из 100 остаётся 80,
из 101 — 80, из 1 — 0. Штраф применяется при каждой смерти к текущему кошельку.
При приближении живого игрока остаток автоматически возвращается в инвентарь.
Повторная смерть до подбора уничтожает предыдущий остаток, даже если новый кошелёк
пуст. Если янтарь уже был подобран, следующая смерть обрабатывается обычным образом.
Уровень, опыт, предметы и улучшения от смерти не теряются.

Одновременно существует только одна потеря янтаря на всё прохождение. Она хранит
уровень, точные мировые координаты гибели и сумму; сохраняется при отдыхе, выходе,
загрузке и переходах между уровнями. Маркер без гравитации появляется только на
нужном уровне и подписан «Вернуть янтарь: N». Враги и мёртвый игрок его не подбирают.
Баланс и потеря меняются одной операцией в момент смерти, до анимации возрождения;
подбор также сохраняет одновременно новый баланс и удаление потери.

Новая игра сбрасывает персонажа, флаги мира и место возвращения и записывает новый
слот после загрузки стартового уровня. Меню предупреждает о замене прохождения.

## Что реализовано

| Блок файла | Содержание |
| --- | --- |
| `scene`, `rest_id`, `checkpoint` | Сцена последнего отдыха, постоянный ID restpoint, запасные координаты |
| `player.inventory` | Предметы по `ItemData.id`, количество и порядок стопок, янтарь, улучшения оружия |
| `player.attributes` | Сила, ловкость, интеллект, выносливость, мудрость, множитель скорости действий |
| `player.progression` | Уровень и текущий опыт |
| `player.equipment` | Все слоты экипировки, оба набора оружия, активный набор и режим действий |
| `player.quick_access` | Назначения и выбранный быстрый слот |
| `player.ranged`, `player.throwing` | Стрелы, болты и оставшиеся метательные заряды |
| `world` | Активированные restpoint, открытые тестовые сундуки, завершённые выходы уровня |
| `lost_amber` | Пустой словарь или `{scene, position, amount}` с единственным возвращаемым остатком янтаря |
| `version`, `date`, `play_seconds` | Версия формата, дата записи и время активной игры без паузы |

Принадлежность фляг сохраняется в инвентаре. Максимум зарядов пока определяется
ресурсом предмета; индивидуальной прокачки фляг ещё нет.
Улучшение оружия в текущей игре общее для `ItemData.id`, а не для отдельной копии.
Разделённые стопки при восстановлении не объединяются.

Временные HP/MP, израсходованные заряды фляг, баффы, дебаффы, скорость движения,
анимации, снаряды и положение персонажа между restpoint в файл не записываются.
Обычные мешки добычи, выпавшие осколки янтаря и выброшенные предметы временные:
при пересоздании уровня они исчезают. Уже подобранное остаётся в инвентаре.

## Когда происходит запись

- При начале новой игры и после загрузки сцены прохождения.
- После успешного отдыха и изменения контрольной точки.
- После изменения инвентаря, янтаря, улучшений, характеристик, уровня и опыта.
- После изменения экипировки, наборов оружия и быстрых слотов.
- После расходования или пополнения боеприпасов и метательных зарядов.
- После изменения постоянных флагов мира.
- После смерти, перед переходом уровня, выходом в меню и штатным закрытием игры.
- Кнопка «Сохранить игру» в паузе немедленно записывает текущее прохождение.

Сигналы изменений ставят отложенную запись. Синхронные изменения одной операции
попадают в один снимок: например, покупка предмета вместе со списанием янтаря.
Для будущей одноразовой награды выдача предмета и отметка источника должны
происходить в одной синхронной операции **без `await` между ними**.
После аварийного завершения может потеряться ещё не записанная часть текущего кадра.

Ошибка записи показывается поверх игры; повторная попытка происходит через пять
секунд или при следующем изменении. Выход в меню, закрытие игры и переход уровня
отменяются при ошибке записи, чтобы можно было повторить попытку.
Возрождение после смерти продолжает использовать актуальное состояние в памяти,
даже если диск недоступен.

## Файлы и совместимость

- `user://checkpoint.cfg` — основной слот, ConfigFile, формат **3**.
- `user://checkpoint.cfg.bak` — предыдущая корректная запись.
- `user://checkpoint.cfg.tmp` — временный файл новой записи.
- `user://settings.cfg` — отдельные настройки; новая игра их не сбрасывает.

Новая запись сначала полностью сохраняется во временный файл и читается обратно
для проверки. Корректный старый слот копируется в резервный; затем временный файл
переименовывается в основной в той же директории. Повреждённый основной файл
не перезаписывает корректную резервную копию. При недоступности/повреждении основного
слота загрузка пробует резервный, о чём сообщает меню. Резервная копия — предыдущий
снимок, поэтому последние изменения в ней могут отсутствовать; сразу после новой
игры она может относиться к предыдущему прохождению.

Проверяются версия, наличие сцены, конечные координаты, структура компонентов,
типы значений и известные ID предметов. Файлы больше 4 МиБ отклоняются.
Неизвестный предмет не удаляется молча: снимок отклоняется, пробуется резервный.
Это локальное сохранение, без шифрования и защиты от ручного изменения значений.

Старый формат **1** поддерживается: из него читаются сцена и координаты.
Персонаж получает начальное снаряжение, поскольку в старом формате его прогресса
не было. Формат **2** также читается: существовавший прогресс сохраняется, потеря
янтаря считается отсутствующей. Следующая запись переводит слот в формат 3.
Неизвестные версии и некорректные данные потери отклоняются.

## Устройство реализации

- `features/save/PlayerSaveData.gd` — стабильные ключи компонентов, преобразование
  ресурсов предметов в ID, проверка и восстановление персонажа.
- `features/save/SaveStore.gd` — чтение, проверка файла, миграция и резервная запись.
- `features/save/SaveService.gd` — состояние прохождения, автосохранения, флаги,
  переходы, возвращение к restpoint и пересоздание обычных врагов.
- `features/loot/LostAmberPickup.tscn` — неподвижный маркер потери с областью подбора.
  Спрайт и коллизия имеют единичный локальный масштаб, размер задан корнем сцены.
  Сервис проверяет текущий экземпляр маркера и запрещает двойной подбор.
- `game/menu/GameFlow.gd` создаёт сервис дочерним узлом `Saves`; отдельный autoload
  в `project.godot` не нужен. Существующий `save_checkpoint()` сохранён как API
  совместимости, но теперь записывает полное прохождение.

Каталог предметов строится из `game/items/**/*.tres`, кроме `templates/`.
Используется `ResourceLoader.list_directory`, поддерживающий имена ресурсов в PCK.
Предметы должны иметь непустой уникальный `ItemData.id`. Смена пути ресурса внутри
каталога допустима, смена ID требует миграции. При экспорте включайте **все ресурсы
каталога предметов**, в том числе не используемые напрямую сценами.

Восстановление происходит после готовности сцены в порядке приоритетов компонентов:
инвентарь → характеристики → экипировка и остальные данные → быстрые слоты.
Затем пополняются здоровье, мана и фляги. Во время восстановления автосигналы
не создают промежуточных сейвов. Стабильные ключи файла не зависят от имён узлов
компонентов. Для диска не используются ссылки на `ItemData` или другие объекты.

Сервис активируется через `GameFlow.start_game()`. Запуск отдельной тестовой сцены
из редактора сам по себе не перезаписывает пользовательский сейв; сохраняется
старое локальное поведение возрождения. Полную систему проверяйте через главное меню.

## Подключение постоянного объекта

1. Добавьте экспортируемый `save_id`, уникальный **в пределах уровня**. Задавайте
   его экземпляру в сцене, а не общим значением шаблона. Не меняйте ID после релиза.
2. Добавьте узел в группу `persistent_world` в `_ready()`.
3. Реализуйте `restore_persistent_state()`: сервис вызовет его после готовности сцены.
4. Читайте `GameFlow.saves.get_flag(self, save_id, "opened", false)` и меняйте состояние
   через `GameFlow.saves.set_flag(self, save_id, "opened", true)`.
5. Вместе с наградой запишите флаг её получения, чтобы повторная загрузка не выдала
   награду второй раз. При частичном подборе сохраняйте остаток содержимого.

Флаг адресуется сочетанием `путь сцены::ID объекта::имя флага`. Значения — простые
строки, числа, bool, массивы и словари. Пока нет готового уровня с постоянным ID,
путь сцены служит идентификатором уровня; перенос `.tscn` потребует миграции.

Для старых объектов с пустым `save_id` доступен запасной ID по пути узла.
Он не устойчив к переименованию/переносу узла, поэтому для новых объектов ID
обязателен по соглашению. В MovementSandbox ID назначены restpoint, сундуку и выходу.
Если restpoint переместить, загрузка найдёт его по ID и возьмёт новую позицию.
Если точка удалена, используются сохранённые запасные координаты.

## Проверка

`tests/save_runtime_check.gd` проверяет запись на диск, полный перенос персонажа,
разделённые стопки, флаги сундука, координаты по ID, отдых/возрождение врагов,
переход уровня, смерть, пополнение фляг, резервный файл, повреждения, неизвестные
предметы, старый формат и чистую новую игру. Запуск только с изолированным профилем
в `.godot/`, чтобы не затронуть настоящее прохождение. Команды — в `docs/Testing.md`.

`tests/lost_amber_runtime_check.gd` отдельно проверяет штраф и округление, смерть
с отключённым инвентарём, повторную смерть с пустым и непустым кошельком, выход
во время смерти, загрузку, переходы, двойной подбор, реальные физические контакты,
новую игру и миграцию старого сейва без потери.
